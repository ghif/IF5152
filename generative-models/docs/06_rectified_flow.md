# Rectified Flow & Flow Matching: Straight-Line ODE Trajectories

A foundational guide and code walkthrough for Continuous Normalizing Flows and Flow Matching via Rectified Flow, detailing straight-line vector field regression, classifier-free guidance, and numerical ODE solvers implemented in [06_rectified_flow_cifar10.py](../06_rectified_flow_cifar10.py).

---

## 1. Core Concept & Problem Formulation

Standard diffusion models (such as DDPM and continuous-time VP SDEs) map complex data distributions to Gaussian noise by simulating Brownian motion and score-based drift. While expressive, traditional diffusion paths are fundamentally **curved and stochastic**:
1. **Curvature Bottleneck**: The probability flow ODE underlying continuous diffusion exhibits high curvature near low noise levels, requiring many discretization steps (often 50–1000 neural function evaluations, NFEs) to integrate accurately without severe truncation errors.
2. **Computational Overhead**: Generating high-fidelity samples requires dense trajectory sampling, severely limiting real-time deployment.

**Rectified Flow** (Liu et al., 2023; Lipman et al., 2023) reformulates generative modeling through **Flow Matching** along optimal transport-inspired straight paths. Rather than simulating curved stochastic diffusion, Rectified Flow defines an explicit, deterministic straight-line interpolation between authentic data and standard Gaussian noise:

```
Data Distribution p_data (t = 0)  ----------------------->  Prior Noise N(0, I) (t = 1)
       x_0 = x                                                    x_1 = z
                     Straight Trajectory: x_t = (1 - t)x + tz
```

By enforcing straight trajectories, the ground-truth velocity field governing the transformation is constant with respect to time along each path. A neural network is trained to predict this velocity field via standard mean squared error (MSE) regression. At inference time, high-quality images can be generated by integrating backwards from $t = 1$ to $t = 0$ using simple numerical ODE solvers (such as Euler or Heun) in as few as 10–25 steps.

## 2. Mathematical Foundation & Velocity Field Derivation

### 2.1 Straight-Line Probability Paths

Let $x \sim p_{\text{data}}$ be a clean training image and $z \sim \mathcal{N}(0, I)$ be an independent standard normal noise vector of identical spatial dimension. For continuous time $t \in [0, 1]$, define the linear interpolation path:

$$
x_t = (1 - t)x + t z
$$

This linear interpolation path satisfies explicit boundary conditions:

$$
x_0 = x \quad (\text{data at } t = 0), \qquad x_1 = z \quad (\text{Gaussian noise at } t = 1)
$$

### 2.2 Constant Ground-Truth Velocity Field

Differentiating the linear path $x_t$ with respect to time $t$ yields the instantaneous velocity:

$$
v_{\text{gt}}(x_t, t) = \frac{\mathrm{d}x_t}{\mathrm{d}t} = \frac{\mathrm{d}}{\mathrm{d}t}\Big[(1 - t)x + t z\Big] = z - x
$$

Notice that along any sampled realization pair $(x, z)$, the velocity is **constant** and points directly from the data point $x$ toward the noise vector $z$.

### 2.3 Flow Matching Objective

Because the true marginal vector field $v(x_t, t) = \mathbb{E}[z - x \mid x_t]$ is analytically intractable, we train a parameterized neural network $v_\theta(x_t, t, y)$ to minimize the expected $\ell_2$ regression error across random timesteps $t \sim \mathcal{U}(0, 1)$:

$$
\mathcal{L}_{\text{RF}}(\theta) = \mathbb{E}_{x \sim p_{\text{data}},\, z \sim \mathcal{N}(0, I),\, t \sim \mathcal{U}(0, 1),\, y}\Big[ \big\| v_\theta(x_t, t, y) - (z - x) \big\|_2^2 \Big]
$$

Unlike diffusion score matching, which requires estimating the score function $\nabla_{x_t} \log p_t(x_t)$ weighted by noise variance schedules, Rectified Flow training is simple regression against the target displacement $z - x$.

### 2.4 Classifier-Free Guidance (CFG) in Velocity Space

To generate class-conditional samples (e.g., specific CIFAR-10 classes) while maintaining high sample fidelity, Classifier-Free Guidance is applied directly in velocity space:

1. **Training Phase**: With dropout probability $p_{\text{uncond}} = 0.15$, the true class label $y \in \{0, \dots, 9\}$ is replaced with an unconditional null token $y_{\emptyset} = 10$.
2. **Inference Phase**: Given guidance scale $s \ge 1.0$, the guided velocity $v_{\text{cfg}}$ extrapolates away from the unconditional velocity toward the class-conditioned velocity:

$$
v_{\text{cfg}}(x_t, t, y) = v_\theta(x_t, t, y_{\emptyset}) + s \cdot \Big( v_\theta(x_t, t, y) - v_\theta(x_t, t, y_{\emptyset}) \Big)
$$

When $s = 1.0$, standard conditional sampling is recovered. When $s > 1.0$ (e.g., $s = 2.0$), class-specific features are amplified, improving sample clarity and class separation.

### 2.5 Reverse ODE Sampling

At inference time, generation starts from pure Gaussian noise $x_1 \sim \mathcal{N}(0, I)$ at $t = 1$ and proceeds backward toward $t = 0$. The reverse Ordinary Differential Equation is:

$$
\frac{\mathrm{d}x_t}{\mathrm{d}t} = v_\theta(x_t, t, y) \implies x_{t - \Delta t} = x_t - \int_{t - \Delta t}^{t} v_\theta(x_\tau, \tau, y) \, \mathrm{d}\tau
$$

Because the trajectories are approximately straight lines in state space, numerical integration requires far fewer discretization steps than traditional diffusion reverse SDEs.

## 3. Architecture & Code Walkthrough (`06_rectified_flow_cifar10.py`)

The companion script [06_rectified_flow_cifar10.py](../06_rectified_flow_cifar10.py) implements the complete pipeline for class-conditional Rectified Flow on CIFAR-10 ($3 \times 32 \times 32$).

### 3.1 Continuous Harmonic Time Embeddings (`SinusoidalTimeEmbedding`)

Continuous scalar time $t \in [0, 1]$ is scaled by 1000 to match standard diffusion harmonic frequencies and mapped into a high-dimensional sinusoidal embedding:

```python
class SinusoidalTimeEmbedding(nn.Module):
    def __init__(self, dim: int):
        super().__init__()
        self.dim = dim

    def forward(self, t: torch.Tensor) -> torch.Tensor:
        t_scaled = t * 1000.0
        half_dim = self.dim // 2
        freqs = torch.exp(
            -math.log(10000.0)
            * torch.arange(start=0, end=half_dim, dtype=torch.float32, device=t.device)
            / half_dim
        )
        args = t_scaled[:, None] * freqs[None, :]
        embedding = torch.cat([torch.sin(args), torch.cos(args)], dim=-1)
        return embedding
```

### 3.2 Conditioning & Multi-Head Self-Attention

Conditioning is handled by combining time embeddings with class embeddings:
- `ConditionalResBlock`: Injects the conditioning vector $c = \text{Embed}(t) + \text{Embed}(y)$ into residual blocks via a SiLU linear projection spatially broadcast across feature maps.
- `AttentionBlock`: Evaluates spatial multi-head self-attention using PyTorch's optimized `F.scaled_dot_product_attention`, placed at the $16 \times 16$ and $8 \times 8$ resolutions and the $4 \times 4$ bottleneck.

### 3.3 U-Net Velocity Backbone (`RectifiedFlowUNet`)

The architecture employs a multi-scale U-Net encoder-decoder:
- **Input**: Noisy image $x_t \in \mathbb{R}^{B \times 3 \times 32 \times 32}$, continuous time $t \in [0, 1]$, and class label $y \in \{0, \dots, 10\}$.
- **Encoder**: 3 downsampling stages ($32 \times 32 \to 16 \times 16 \to 8 \times 8 \to 4 \times 4$) with residual blocks, strided convolutions, and self-attention.
- **Bottleneck**: Two residual blocks flanking a self-attention layer at $4 \times 4$ resolution.
- **Decoder**: 3 upsampling stages utilizing transposed convolutions (`nn.ConvTranspose2d`), skip concatenations from encoder stages, residual blocks, and self-attention.
- **Output**: Linear $3 \times 3$ convolution predicting the velocity vector field $v_\theta \in \mathbb{R}^{B \times 3 \times 32 \times 32}$.

### 3.4 Rectified Flow Engine (`RectifiedFlow`)

The `RectifiedFlow` class encapsulates the trajectory math and loss computation:

```python
class RectifiedFlow:
    def get_train_tuple(self, x: torch.Tensor, device: torch.device):
        b = x.size(0)
        z = torch.randn_like(x)
        t = torch.rand(b, device=device)
        t_spatial = t[:, None, None, None]

        # Straight-line trajectory
        x_t = (1.0 - t_spatial) * x + t_spatial * z
        v_gt = z - x
        return x_t, t, v_gt, z

    def compute_loss(self, net, x, y, p_uncond=0.15):
        x_t, t, v_gt, _ = self.get_train_tuple(x, x.device)
        # Random label dropout for CFG
        mask = torch.rand(x.size(0), device=x.device) < p_uncond
        y_train = y.clone()
        y_train[mask] = self.null_class

        v_pred = net(x_t, t, y_train)
        return F.mse_loss(v_pred, v_gt), v_pred
```

## 4. Training Dynamics & Numerical ODE Solvers

### 4.1 Comparison: DDPM / DDIM vs. Rectified Flow

| Metric / Property | DDPM (Ho et al., 2020) | DDIM (Song et al., 2020) | Rectified Flow (Liu et al., 2023) |
| :--- | :--- | :--- | :--- |
| **Trajectory Type** | Curved Brownian SDE | Non-Markovian Curved ODE | Straight-line Linear Flow |
| **Prediction Target** | Added noise $\epsilon_\theta(x_t, t)$ | Added noise $\epsilon_\theta(x_t, t)$ | Velocity field $v_\theta(x_t, t) \approx z - x$ |
| **Discretization Schedule** | Strict $\beta_t$ variance schedule | Non-uniform sub-sampled timesteps | Uniform continuous $t \in [0, 1]$ |
| **Inference NFEs** | 500 – 1000 steps | 50 – 100 steps | 10 – 25 steps |
| **ODE Solvers** | Ancestral sampling | Euler-like step on curved manifold | First-order Euler or Second-order Heun |

### 4.2 Numerical Solvers in `sample_ode`

Sampling integrates backwards from $t_0 = 1.0$ down to $t_N = 0.0$ in $N$ uniform steps of step size $\Delta t = \frac{1}{N}$:

#### 1. First-Order Euler Solver (`solver="euler"`)

Given current state $x_t$ and guided velocity $v_{\text{cfg}}(x_t, t, y)$, the next state is updated linearly:

$$
x_{t - \Delta t} = x_t - \Delta t \cdot v_{\text{cfg}}(x_t, t, y)
$$

This requires **1 NFE per step** (or 2 evaluations with CFG: conditioned + unconditioned).

#### 2. Second-Order Heun Predictor-Corrector (`solver="heun"`)

Heun's method improves numerical stability by evaluating velocity at an intermediate predicted point:

1. **Predictor Step**:

$$
\tilde{x}_{t - \Delta t} = x_t - \Delta t \cdot v_{\text{cfg}}(x_t, t, y)
$$

2. **Corrector Step**:

$$
x_{t - \Delta t} = x_t - \frac{\Delta t}{2} \cdot \Big[ v_{\text{cfg}}(x_t, t, y) + v_{\text{cfg}}(\tilde{x}_{t - \Delta t}, t - \Delta t, y) \Big]
$$

Heun's solver achieves second-order error $\mathcal{O}(\Delta t^2)$, allowing high-fidelity generation in as few as 10–15 steps at the cost of 2 evaluations per step.

### 4.3 Exponential Moving Average (EMA)

To stabilize the vector field predictions against gradient variance, an EMA tracker (`EMAModel`) maintains shadow weights with decay $\beta = 0.999$:

$$
\theta_{\text{EMA}} \leftarrow \beta \cdot \theta_{\text{EMA}} + (1 - \beta) \cdot \theta_{\text{model}}
$$

Evaluation using EMA weights yields sharper image boundaries and eliminates high-frequency sampling artifacts.

## 5. CLI Execution & Practical Usage

The script supports end-to-end training, checkpoint resumption, and sample grid evaluation via command-line arguments.

### 5.1 Training from Scratch

```bash
# Standard training for 50 epochs on GPU with EMA and mixed precision
python 06_rectified_flow_cifar10.py \
    --epochs 50 \
    --batch-size 128 \
    --lr 0.0002 \
    --channels 64 \
    --steps 25 \
    --cfg-scale 2.0 \
    --solver euler
```

### 5.2 Fast Smoke Testing

```bash
# Quick verification test (1 epoch, 50 samples)
python 06_rectified_flow_cifar10.py --quick-test
```

### 5.3 High-Fidelity Sampling from Checkpoint

Generate a $10 \times 10$ class-conditional evaluation grid using the trained EMA weights and Heun's second-order solver:

```bash
python 06_rectified_flow_cifar10.py \
    --eval-grid \
    --use-ema \
    --steps 25 \
    --solver heun \
    --cfg-scale 2.5
```
